# NullSpace 0.8.2

Fixes the server freezes while natural habs are generated. In 0.8.1 a large hab could stop the server for about ten seconds when it finished building, and every hab build caused a run of stalls of a quarter to three quarters of a second. In a local profile of habs built one after another on Terra, the longest tick fell from about 950 ms to about 260 ms, ticks over 200 ms fell from about 36 to 1 for a standard hab and from 39 to 2 for a large one, and a large hab now builds in about 9 seconds instead of 20.

Existing worlds do not need a reset. Habs already built are unchanged. A hab that was part way through building when the server is updated is put back by the journal recovery at the next start and then built again from its saved progress.

## Changes

- **No freeze when a large hab finishes.** Finding which cells of a large hab's air grid are sealed used to be one pass over every block on the server thread (10.6 s for a 5.5 million cell hab). It is now done a few milliseconds a tick while the last blocks go in, and registering the hab takes the result (150 to 400 ms).
- **No journal, and no forced world save, for building a hab.** A hab is a fixed set of blocks at fixed places, so building it is idempotent. Progress is a count of finished chunks kept in the world store, which is saved with the chunks, so after a crash the build resumes a few chunks earlier and sets blocks that are already right again. Each forced save used to stall the server for 260 to 300 ms, once per batch.
- **Smaller pieces of work per tick.** Blocks are set for about 6 ms a tick (at most 4096). The map of what a hab sets is worked out on a worker thread. Commissioning (entities, stock and doors, tree and crew, registration) takes a tick for each piece, and the hab's block list is written by a worker. A hab is marked built only once that list is on disk.
- **Cheaper journals for ships and stations.** A build journal is rewritten only when its records change, written and read back once, and not compared tag by tag. Building a ship or station in a batch no longer writes its journal once per footprint.

## Tooling

- [`scripts/perf/hab_flamegraph.py`](../../scripts/perf/hab_flamegraph.py), [`hab_compare.py`](../../scripts/perf/hab_compare.py) and [`hab_long_ticks.py`](../../scripts/perf/hab_long_ticks.py) turn a Java Flight Recorder recording of hab generation into flame graphs per hab size, a before and after table, and a breakdown of the longest ticks.

## Not changed

World saves from the ordinary autosave, vanilla chunk ticking and the power and air ticking of registered habs were not tuned; a few ticks of 100 to 260 ms remain while a hab is commissioned.
