# NullSpace 0.8.3

Fixes a hab built across a server restart showing its roofs, makes the pad and ship computers' action limit count server ticks, and makes the test suite find every failure in one run.

Existing worlds do not need a reset.

## Changes

- **Habs resumed after a restart are grounded in the terrain.** The stone that covers a natural hab's roofs on gentle slopes was only worked out while the site was being planned, so a build taken up after a restart could leave roofs showing through the ground in the chunks it built afterwards. A resumed build now works that cover out again for the chunks still to build, and for the chunk it stopped in finds the terrain from the world generator where its own blocks may top the column.
- **One action every ten ticks at pad and ship computers.** The limit of one action per half second at a pad computer or a ship controller (a tenth of a second for a system action) was measured in wall-clock time; it now counts server ticks, ten (or two), as the station and ship computer terminals already did. At full speed it is the same; on a lagging server it is longer in real time, in step with everything else.

## Tests and tooling

- A failing graphical test no longer hides the ones after it: [`parallel-test.ps1`](../../scripts/test/parallel-test.ps1) starts a client for the classes that did not run and reports every failure of the run together.
- The graphical tests wait through [`ClientWaits`](../../src/gametest/java/com/nullandkale/nullspace/testing/ClientWaits.java): Fabric's waits, which count ticks, accept a timeout only after 60 seconds of real time, and typing waits for the screen to be free of overlays. Wall-clock pauses are gone.
- Tests that launch ships by any path, pick their own orbit slot or set a static hook run in their own environment; a new test interrupts a hab build part way and checks it finishes the same dungeon.
- A wait in a test no longer gives up after a count of ticks and carries on without what it waited for: two tests did, and failed on the slower release CI runner. They wait with `TestWaits.until`, which pauses in real time while it waits.
- A test's pad registration is no longer refused by a pad left behind by a test in an earlier batch: [`TestPads`](../../src/gametest/java/com/nullandkale/nullspace/testing/TestPads.java) knows a pad's test has finished from the tests that were running when it appeared, not only from whether its computer still stands.
- The crash, restart and multiplayer scripts no longer kill a JVM after a fixed time: they stop one whose logs have stopped growing for three minutes, so a busy machine no longer fails a stage that had passed.
- [`GameTestHygieneTest`](../../src/test/java/com/nullandkale/nullspace/testing/GameTestHygieneTest.java) enforces all of these; the rules are in [test hygiene](../development/test-hygiene.md).
