# 0.5.2 rc1 playtest: November 12

Bug fixes and refactors stay in scope during the feature freeze. Performance work stays deferred. These reports concern rc1; the earlier completed checklist does not cover these corrections.

- [x] Leave a blank line below the Ship Controller tabs and above Fly manually / View ship / Close all doors.
- [x] Show Undock on Trip when it is the available departure action. Keep Continue journey when it can already undock and resume the trip.
- [x] Explain encounter ownership at the core. Make claiming an unowned derelict the main action, explain that the previous ship stays put, and keep construction controls for owners and builders. Claiming already exists; this is a presentation correction.
- [x] Implement the approved full-width map mockup: black background, 18 rows of map height, compact search/View controls and labels beside contacts. Use nearby label positions and leader lines for crowded contacts. The square map and side legend were rejected and reverted.
- [x] Land with the main entrance facing the Pad Computer. The user confirmed the entrance rather than the bow. Rotate the physical hull and everything aboard, including recovery and saved respawn/crew positions.
- [x] Extend generated pad stairs until they meet terrain. Fill underneath raised pads and stair flights so they do not leave a dark spawning space.
- [x] Draw optional room uses from one bag for the whole ship. Use each fitting room before repeating it; mirrored rooms must not automatically share a use.
- [x] Give medium and large twin and dome ships connected decks, as their tiers specify. Turn the solid blocks beside spine stairwells into usable rooms and retain rooms on the upper deck.

The user approved the full-width map mockup on November 12. The UI, generation and physical landing corrections are implemented and verified together. Landing rotation includes MOVE recovery, saved crew/respawn state, air and devices. Existing ships are preserved; layout changes apply to newly generated ships.

For encounter cores, the intended first page is **Unclaimed vessel → Claim vessel** with the ownership consequences above the button. A visitor at a station that cannot be claimed sees that explanation and how to return to their ship. Owners and invited builders retain the construction page. Claiming does not repair the hull or add fuel, engines or supplies.

The [arrival orientation design](../design/pad-arrival-orientation.md) records the transfer, saved-state and recovery work needed for the landing correction.

Review the actual controller pages, chart, encounter core, floor plans and stairs. Structural checks alone do not establish that the layouts or player flow are good.
